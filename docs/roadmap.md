# 향후 작업 (Roadmap)

보류/예정 항목. 우선순위 대략순.

## ✅ 완료: 데이터 경로 분리 (하드닝)

- 런타임 데이터(로그/상태/캐시/생성물)를 소스 트리에서 분리해 고정 `DATA_ROOT`
  (기본 `~/kis_arb_data/`, 환경변수 `KIS_ARB_DATA_DIR`로 재정의)로 이전. 단일 소스는
  `etf_arb/paths.py`. 소스 폴더를 옮기거나 이름을 바꿔도 쌓이는 데이터가 꼬이지 않음
  (과거 디렉토리 중첩으로 데이터가 분리된 사고의 재발 방지). 설정(`etf_arb_config.json`)과
  `.env`는 버전관리/관례상 소스와 함께 유지. 상세: [operations.md](operations.md).

## 1. 종목별 동적 진입 임계값 (2단계) — ~1주 소킹 후

- **현황**: 1단계 완료 — 리프레셔가 종목별 괴리 분위수(p5/p10/p25/median)를 매일
  `expected_disparity`로 워치리스트/후보 파일에 기록 중.
- **할 일**: 이 분위수를 거래 로직에 주입.
  1. 러너가 워치리스트에서 종목별 기대괴리 분위수를 읽어 `signals`에 전달.
  2. `evaluate_entry`가 고정 `entry_threshold_pct`(−0.5%) 대신 `max(전역 최소 임계, 종목별
     분위 기반 임계)`를 사용.
  3. 호가창 유동성 기반 사이징의 자본상한(`max_alloc_per_position_krw`)도 종목별 분포로
     정규화(z-score/분위) 검토 — "이 종목 기준 이례적으로 깊은" 순간엔 상한을 더 높게.
- **전제**: 표본 신뢰성 확보 전(< ~1주 소킹, `intraday_min_samples` 미달)에는 켜지 말 것.
  워치리스트 20종목은 웹소켓으로 촘촘하지만 나머지 80종목은 1분 해상도라 이 차이 반영 필요.
- 배경/근거: [watchlist.md](watchlist.md) "기대괴리 분포" 섹션.

## 2. 원데이(당일) 해소 기반 수익성 검증

- **배경**: 2026-07-23 `0100K0`가 전날(07-22) 진입 후 밤사이 기초가격이 더 떨어져 괴리는
  해소됐지만(정상 청산) 순손실로 마감(누적 실현손익 +345,788 → +328,661). 오버나이트
  캐리(포지션을 다음 거래일로 넘기는 것)가 미세한 괴리 엣지를 방향성 리스크로 뒤집을 수
  있다는 우려가 실측으로 드러난 사례.
- **아이디어**: 워치리스트 선정 시 종목별 "괴리가 보통 당일 장마감 전에 해소되는가"를
  하드필터/스코어에 반영 — 오버나이트로 넘어가기 쉬운 종목은 배제하거나 감점.
- **필요 작업**:
  1. `intraday_episode_stats`가 이미 계산하는 에피소드 소요시간 분위수(median/p90, 분 단위)는
     "N분 이내 해소율"이라 시작 시각에 따라 남은 장중 시간이 다름(09:10 시작 vs 14:50 시작) —
     그대로 재사용 불가. 에피소드별로 **"그날 장마감 전에 해소됐는가"**를 직접 판정하는
     신규 지표 필요.
  2. `mean_net_edge_pct`도 현재는 당일/익일 구분 없이 계산됨 — 당일 해소로 한정한 순엣지를
     별도 계산해야 오버나이트 캐리 없이도 수익성이 있는지 직접 검증 가능.
  3. (즉시 가능, 신규 데이터 불필요) 이미 쌓인 `etf_arb_trades_sim.jsonl`/저널의 완전청산
     왕복 건을 `entry_date == exit_date`(당일청산) vs 익일 이후(오버나이트) 로 나눠 실현
     손익 분포를 비교 — 표본은 아직 적지만(왕복 10회) 거래가 쌓일수록 신뢰도 상승.
- **전제**: 항목 1(동적 진입 임계값)과 같은 소킹 기간 제약 공유 — 에피소드 표본이 쌓일 때까지
  대기. 두 작업은 `intraday_episode_stats` 확장이라는 공통 기반 위에 있어 함께 진행 검토.
- 배경/근거: [watchlist.md](watchlist.md) "기대괴리 분포" 섹션, [operations.md](operations.md).

## 3. Phase 4 — 실전 실행기

- **현황**: 시뮬 전용. 실전 경로는 이중 게이트(`mode="live"`+`live_enabled`)로 잠김, 미구현.
- **할 일**: `order_buy_005930_real.py`를 종목/수량/방향/지정가로 일반화한 `executor_live.py`.
  시장가 아닌 **지정가**(계산된 가격에 거래), 매도 tr_id `TTTC0011U`, 체결조회는 EXCG
  `"ALL"`/`"SOR"`, 부분체결 반영. 시뮬과 동일한 `place_order()` 인터페이스.
- **진입 조건**: 시뮬 손익이 비용 반영 후 양(+)이고 데이터 품질 이슈가 없을 것.

## 4. 청산 측 bid-ladder 실효괴리 더블체크

- 현재 매수만 다단계 호가 VWAP 더블체크. 매도(청산)는 bid1 단일 단계.
- 얇은 매수호가에서 큰 포지션을 청산할 때 실효 청산가가 나빠질 수 있음(2026-07-22 `291630`
  1주씩 분할 매도 실측). 대칭적 bid-ladder 검증 추가 검토.

## 5. 바스켓 재구성 백테스트

- 분봉 데이터 벤더는 대부분 가격만 주고 **장중 iNAV는 없음**. 과거 괴리 백테스트를 하려면
  ETF 구성종목(PDF) + 구성종목 분봉으로 `iNAV = Σ(보유수량×현재가)/발행좌수`를 재구성.
- 우리 유니버스가 국내 기초자산이라 구성종목 분봉 확보가 쉬움. KIS `inquire_component_stock_price`
  (ETF 구성종목시세) 활용 가능. 과거 구성 변경 이력 정합이 관건.
- 대안: 지금처럼 자체 수집(샘플러+웹소켓)을 일주일+ 모아 그 위에서 검증. 1번 소킹과 겹침.

## 6. 모의투자 계좌 재연동

- 현재 `90070000`(계좌-앱키 불일치) 에러로 KIS 모의투자 사용 불가 → 로컬 시뮬로 대체.
- KIS 앱/웹에서 `KIS_PAPER_APP_KEY`에 연결된 정확한 모의 계좌번호 확인 후 `.env`의
  `KIS_PAPER_STOCK` 수정. 모의투자 대회 참가 필요 여부 확인. 상세: [operations.md](operations.md).

## 7. 사소한 개선

- **`disparity_pct` 시그널 로깅 보정**: `entry_signal`/`exit_signal` 저널 이벤트의
  `disparity_pct`가 None으로 찍힘(체결 로그 `disparity_at_fill`엔 정상 기록되므로 데이터 손실은
  없음). 시그널 이벤트에도 실제 괴리 채우기.
- **launchd 실패 알림**: 현재 실패 시 로그 수동 확인만 가능. 알림 메커니즘 없음.

## 8. 콘솔 스크립트 진입점 (`[project.scripts]`)

- **현황**: 현재 모든 스크립트를 `uv run xxx.py` 형태로 직접 실행. 콘솔 스크립트 진입점으로
  바꾸면 `uv run <명령이름>`처럼 짧아지고 launchd `ProgramArguments`도 정리되지만, 스크립트가
  아직 자주 바뀌는 중이라 지금 하면 재작업이 잦음.
- **보류 사유(명시적 결정)**: "소스코드가 안정화되어 크게 수정할 부분이 없을 때 진행" — 사이징
  재설계 등 트레이딩 로직이 계속 바뀌는 현재는 우선순위 낮음.
