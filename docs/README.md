## 기본 원리

이 프로젝트는 두 부분으로 구성됩니다.

1. **KIS/KRX 단독 조회·주문 스크립트** — 한국투자증권(KIS) Open API로 현재가/잔고/체결/외화
   예수금을 조회하고, KRX Open API로 국내 상장 ETF 전체 목록을 받는 참고 구현들.
2. **ETF NAV 괴리율 평균회귀 자동매매 시스템** (`etf_arb/` 패키지) — 아래가 핵심.

### ETF NAV 괴리율 평균회귀 전략

ETF는 두 가지 가격을 가집니다.

- **시장가(호가/체결가)**: 거래소에서 실제로 사고파는 가격.
- **NAV(순자산가치)**: ETF가 담고 있는 기초자산 바스켓의 실시간 이론가. KIS 웹소켓
  `H0STNAV0`으로 실시간 추정 NAV(iNAV)를 받습니다.

정상적으로는 두 값이 거의 같지만, 유동성/수급 때문에 일시적으로 벌어집니다(괴리). 전략은:

- **매도1호가가 NAV보다 일정 % 이상 싸지면(음의 괴리)** → 저평가로 보고 **매수**
- **괴리가 해소되면(호가가 NAV로 회복)** → **매도**

방향성 베팅("주가가 오를 것")이 아니라 **상대가치(basis) 트레이드**("시장가가 NAV로
수렴할 것")입니다. 시장 방향 노출이 작고, 국내 기초자산 ETF만 대상으로 해 NAV가 신선하며,
보유기간이 짧게(기본 5거래일 강제청산) 묶여 있어 구조적으로 저리스크입니다.

### ⚠️ 핵심 잔여 리스크: 오버나잇 기초자산 변동

완전 무리스크는 아닙니다. **가격이 NAV로 수렴하더라도, 보유 기간 동안 NAV(=기초 바스켓)
자체가 움직이면 절대 손익은 반대로 날 수 있습니다.** 특히 익일 이월 시 오버나잇 기초자산
변동이 미세한 괴리 엣지(~0.5%)를 압도할 수 있습니다. 실측 사례:

- **2026-07-20 `0018C0`**: 괴리는 정확히 해소(-0.58% → +0.36%)됐지만 그 사이 NAV가 하락해
  실현손익 **-2,435원**.
- **2026-07-21 `488080`(레버리지)**: 밤사이 반도체 급등으로 NAV가 39,700→45,174 폭등, 청산
  이익 **+311,485원** — 이는 괴리 차익이 아니라 오버나잇 방향성 노출에서 나온 것.

즉 이 전략의 엣지는 작고, 개별 왕복 손익은 오버나잇 베타에 크게 흔들립니다. 그래서
[trading.md](trading.md)의 사이징/더블체크와 [watchlist.md](watchlist.md)의 선정 필터로
불리한 진입을 줄이고, 통계적으로 검증하는 것이 중요합니다.

### 실행 모드: 현재 시뮬레이션 전용

매매 시스템은 **로컬 가상 체결(시뮬레이션)로만** 동작합니다. 실제 시세로 "샀다면 어땠을지"를
정확히 계산하지만 KIS에 실주문은 안 나갑니다. 실전 주문 경로는 이중 게이트
(`execution.mode="live"` + `live_enabled=true`)로 잠겨 있고 기본값은 꺼져 있습니다.

> 예외: 단독 스크립트 `order_buy_005930_real.py`는 `--live` 플래그로 실전 주문이 가능합니다.
> 자동매매 시스템과 별개이니 사용에 주의하세요.

## 파일 구조

### 단독 조회/주문 스크립트 (프로젝트 루트)

| 파일 | 역할 |
|---|---|
| `kis_common.py` | KIS 공통 인증(OAuth 토큰 발급/캐시), 시크릿 마스킹, 자격증명 로드 — 모든 KIS 스크립트가 재사용 |
| `kis_price.py` | 삼성전자(005930) 현재가 조회 (참고 구현) |
| `kis_foreign_balance.py` | 실전 계좌 외화 예수금 조회 (TTTC2101R) |
| `kis_paper_balance.py` | 모의투자 계좌 잔고 조회 (VTTC8434R) |
| `kis_check_order_status.py` | 주문번호로 체결 여부 조회 (TTTC0081R) |
| `krx_etf_list.py` | KRX Open API로 국내 상장 ETF 전체 목록 조회 (etf_bydd_trd) |
| `order_buy_005930.py` | 모의투자 계좌 005930 매수 (계좌 미연동으로 현재 사용 불가) |
| `order_buy_005930_real.py` | ⚠️ 실전 계좌 005930 1주 시장가 매수 (`--live` 필요, 안전패턴 참조 구현) |
| `run_order_once.sh` | launchd/cron 1회성 주문 실행 래퍼 |

### 일일 파이프라인 스크립트 (프로젝트 루트)

| 파일 | 역할 |
|---|---|
| `etf_universe_select.py` | 콜드스타트용 초기 워치리스트 생성 (수동, 종가 기준) |
| `etf_watchlist_refresh.py` | 매일 08:15 — KRX 전종목 + 장중 누적 데이터로 재스코어링해 감시 20종목 선정 |
| `etf_intraday_sampler.py` | 매일 08:56 — 후보 ~100종목의 현재가/NAV/괴리율/스프레드를 1분 주기 REST 폴링해 축적 |
| `etf_arb_run.py` | 매일 08:50 — 웹소켓으로 감시 20종목 실시간 관찰 → 시그널 평가 → 가상 체결 |
| `etf_arb_report.py` | 체결/저널 기반 손익·통계 리포트 |

| `ws_client.py` | KIS 웹소켓(NAV `H0STNAV0` + 10단계 호가 `H0STASP0`) 클라이언트, 접속키/재접속 |

| `executor.py` / `executor_sim.py` | 실행기 인터페이스 + 시뮬 체결(호가 사다리 VWAP) |
| `journal.py` | JSONL 이벤트 저널 |
| `runner.py` | 오케스트레이터 (기동 시퀀스, asyncio 루프, 종료) |

### 설정/데이터 파일

**설정(`etf_arb_config.json`)과 `.env`만 소스 트리에 있고, 나머지 런타임 데이터는 소스 밖
`DATA_ROOT`(기본 `~/kis_arb_data/`, 환경변수 `KIS_ARB_DATA_DIR`로 재정의)에 쌓입니다.**
소스 폴더를 옮겨도 데이터가 꼬이지 않도록 경로를 소스와 독립적으로 해석합니다(과거 디렉토리
중첩 사고 재발 방지). 상세는 [operations.md](operations.md)의 "로그 & 상태 파일" 참조.

| 파일 | 위치 | 설명 |
|---|---|---|
| `etf_arb_config.json` | **소스 트리** | 모든 임계값/한도/모드 (전 필드 설명은 [trading.md](trading.md) config 표) |
| `.env` | **소스 트리** | KIS/KRX 자격증명 (gitignore) |
| `etf_watchlist.json` | `$DATA_ROOT/` | 리프레셔가 매일 생성하는 감시 20종목 |
| `etf_candidates_ranked.json` | `$DATA_ROOT/` | 상위 100종목 후보 풀, 샘플러가 소비 |
| `data/` `state/` `logs/` `cache/` | `$DATA_ROOT/` | 런타임 캐시/상태/로그/토큰캐시 |

전체 실행 절차와 요구사항은 최상위 [../README.md](../README.md)를 참고하세요.
